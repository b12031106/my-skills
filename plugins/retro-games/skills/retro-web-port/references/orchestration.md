# 子代理分工與模型規則

## 選擇與授權

以下為 Codex 環境的預設分工政策，允許在實際開發委派時依任務套用列出的模型／思考等級。其他 coding agent 按 [跨 agent 適配](agent-compatibility.md) 選本地模型，不強制使用 GPT。使用者明確指定模型、成本上限或不准委派時，以其指示為準。先檢查環境實際提供的模型、思考等級及並行限制；名稱不是永久能力或價格保證，不虛構不存在的選項。

| 工作 | 預設模型／思考等級 | 判斷條件 |
|---|---|---|
| 主控、拆解、整合與一般覆核 | GPT-6.1 Sol／medium | 足夠處理多項關聯；重要逆向簽核可用 high |
| 局部實作、介面、測試、人工存檔製作 | GPT-6 Luna／high | 規則已有證據、介面明確、範圍受控 |
| 未知原版規則、組合語言、AI、亂數、存檔與共用狀態 | GPT-6.1 Sol／high | 需要建立證據或跨模組推理 |
| 換方法仍卡住的關鍵難題 | GPT-6 Astra／high | 限定一個高影響問題，不設為日常預設 |
| 已穩定版本的最後自然遊玩與問題記錄 | GPT-6 Luna／high | 遵循流程、保存檢查點；疑難問題交回主控 |

主 session 的模型若不能由工具切換，不宣稱已切換；在現有模型下總控，必要時委派可用的調查者。指定子代理模型須使用工具支援的上下文模式；若完整歷史繼承不支援覆寫，改用局部歷史或明確任務資料。沒有指定模型能力時沿用可用模型，不自行創建新 session 當替代。

以未知程度、影響範圍與失敗代價決定模型，而非程式碼行數。對 Luna 的連續失敗先分析／縮小問題再升級；不能讓便宜代理無限重試。高思考、重複傳背景、多人重跑和返工都會提高總用量，不能保證低階模型必然省錢。只在要討論當前價格或產品限制時查官方資訊。

## 任務契約

每個任務交付這些資訊，篇幅隨任務調整：

- TODO 編號、具體缺口、玩家影響與完成範圍。
- 原版證據位置、可信度、需要查證的未知；不能以猜測補齊的欄位。
- 接口與前後狀態、允許修改檔案、不得修改的共用區域。
- 最小驗收案例、固定亂數／存檔來源、需要的 UI 操作及預期結果。
- 回報需包含改動、證據、實際執行的檢查、限制與產物位置。

可以交付研究任務，但需有可用於後續實作的具體結論或不可判定邊界；避免產出沒有接入用途的大型報告。實作完成不包括自行 push、部署或替主控核准整體功能。

## 並行與所有權

依實際並行額度保留主控及必要覆核空間；額度四人時可先採主控＋兩名開發＋一個彈性調查／覆核席。沒有獨立任務就不用填滿名額。

多人不得同時寫相同檔案；最初由主控分配所有權。核心入口、共用狀態、TODO 與最後整合通常由主控持有。拆不開的改動序列化；或按專案既有慣例用隔離工作樹並由主控整合，不為並行而丟失尚未提交的修改。

瀏覽器、原版遊戲視窗與共用測試服務屬可變資源：輪流操作或使用獨立 origin／profile／連接埠，不可互相覆寫畫面與儲存。測試服務記錄所有者及識別，只停止自己啟動的服務。

相關任務可沿用已理解該系統的代理；領域切換或上下文污染時才換新代理。不要每個小步都重建全部背景。子代理不能無限制再委派；主控掌握全隊額度與檔案所有權。

## 簽核與接續

子代理自測 → 主控讀實際差異與原版證據 → 整合 → 針對受影響路徑重現關鍵操作 → 必要回歸 → 主控更新 TODO → 派下一批。

主控不必重跑子代理每一項低風險檢查；依改動檢查可信證據。跨狀態、共用亂數、存檔和關鍵流程必須在整合版本確認。測試預期如果直接來自新實作本身，不能當作獨立原版 oracle。

未能簽核就保留未完成／部分完成及原因，不以代理回報數量衡量進度。對失敗回覆具體差異與新的查證方向；完成一項不需向使用者詢問是否繼續。
