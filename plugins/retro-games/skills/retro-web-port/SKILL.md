# 老遊戲 Web 移植總控

## 目標與適用方式

將指定老遊戲的原版內容與可連續遊玩的流程移植為原生 Web，再納入使用者要求的加強功能。先還原，再加強；素材抽取、看似合理的自創玩法、測試全綠都不能取代還原證據。不得用模擬器作為移植實作或驗收手段；依可用且獲授權的環境操作原版。

一個 skill 涵蓋起步、中途接手與收尾。依實際檔案與最新證據選擇階段，不另建互相矛盾的工作流程。若使用者只要求詢問、報告或單項修改，維持該範圍；只有要求自主推進時才持續處理後續項目。

## 接手與選擇階段

1. 先讀專案規範（例如 `AGENTS.md`、`CLAUDE.md`）、`TODO.md`、目前變更、相關進度與既有測試。保留修改，核對文件與現況；不重做已完成的探索，也不因舊報告通過就認定最新版已驗收。
2. 確認本次是哪個遊戲／版本／目標範圍，原檔、移植程式、素材與存檔所在位置，以及其他代理或 session 的修改範圍。不把另一代或另一款遊戲的規則直接套用。
3. **起步**：沒有可信的程式／資料地圖時，先建立最小檔案清單與來源指紋、格式／模組關係，再選一個具代表性的可驗證垂直流程。避免先做大量外觀或寫出整套猜測引擎。
4. **中途**：從已知差異與中斷選下一缺口；沿用既有工具、模組和證據，只補本次需要的探索。
5. **收尾**：先以 debug／god mode 走完最新版實際流程、分支與結局，排除銜接障礙。基礎障礙都排除後，才依使用者目標決定是否做正常數值／難度的自然遊玩驗收；不得把正常難度破關當成前期開發的必要門檻。

資訊不足時，先做不依賴答案的讀取與查證；只有實際阻礙範圍或操作的資訊才向使用者詢問。

## 證據與逆向

每個還原結論分開記錄：**原始資料已證實、原程式分析已證實、原版操作已證實、Web 操作已驗證、尚未驗證的推測**。其中 Web 結果只證明移植行為，不能單獨證明原版規則。

追查事件觸發、讀寫欄位、呼叫者、跨回合／場景狀態與亂數消耗，不只解析素材。從玩家可觀察差異回溯最短相關程式路徑；原版不能執行時用靜態分析、資料與既有紀錄推進，明列原操作缺證。

未知的旗標、繪圖／音訊前史、亂數或存檔欄位保留未知；不以 0、預設值或合理猜測冒充原版狀態。需要暫時 fallback 時明示限制，隔離於已證實規則之外。忠實還原與加強操作分開驗證，加強操作不得悄悄改變核心數值或事件。

加強版需求從該專案的使用者交辦與 TODO 接續，例如劇情 Skip、拖曳／縮放戰場、小地圖、Hover 狀態／範圍、右鍵取消、裝備比較與更多存檔欄位。這些是需求檢查的例子，不自動要求每款遊戲全部新增；已有功能要檢查新改動是否造成回歸。

## 持續工作循環

按玩家影響排列：流程中斷／存檔損壞 → 核心資料與玩法錯誤 → 缺失事件／跨場景承接 → 介面與演出 → 時序／音訊精度。實際需求可調整優先序。

反覆執行：選下一個重要且可驗證的缺口 → 查證原版 → 定義前後狀態及完成條件 → 實作 → 局部測試 → 實際操作 → 修正 → 更新 TODO → 接下一項。

不要等整個逆向完成才做可玩的接入，也不要只寫底層模組而留下所有呼叫端。大項拆成研究、底層、接入與驗收；每一部分的完成範圍明示。自主工作時不因一個階段完成而結束，也不問是否繼續。

同一問題連續兩次無進展，先診斷缺的是證據、工具、重現案例還是實作方法，再縮小案例、換來源、調整模型或交由主控分析。單項被阻擋就記錄原因，繼續不依賴它的有價值工作。

## 子代理與主控

**明確委派授權：使用者要求以本 skill 推進移植／開發時，授權目前 agent 自行擔任主控，主動喚起、指派、協調與接續子代理工作，並依分工表選擇可用的模型及思考等級。主控不需要為每次建立子代理、派發任務、重新分派或在表內升級模型另行取得使用者確認。此段明確要求自主子代理協作，不是只有介紹多代理策略。**

有可獨立交付的研究、實作或驗收任務且子代理工具可用時，主控應實際委派，指定檔案所有權、證據及驗收條件，並持續完成整合與簽核。短小、強依賴或拆分成本大於收益的步驟由主控直接做，不為填滿名額而委派。使用者只要求解說／報告、明確禁止委派或設有預算限制時，維持其範圍與限制。

授權限於本次專案目標與宿主提供的子代理工具，不包含創建獨立的使用者 session、外部付費服務或擴張操作權限；不得繞過更高優先級的限制。主控將任務內必要的委派授權、修改邊界與驗收責任傳達給子代理，管理全隊額度，避免子代理無限制再委派。

委派或選擇模型前讀 [子代理分工與模型規則](references/orchestration.md)。主控負責跨模組狀態、整合與最終簽核；不接受只有「完成／通過」的自我聲明。沒有子代理工具時採單代理循環，維持同樣證據與驗收要求，不因此停止。

低／中風險且可獨立驗證的子任務先試可用的較省成本模型，依主控確認的交付結果升級與校正下次路由；未知逆向與高影響共用狀態可直接跳級。按參考文件維護專案模型觀察紀錄，每個任務指定驗收範圍及進度檢查點，子代理不得自發擴大為長時間整套測試。

在 Claude Code 或其他 coding agent 使用時，另讀 [跨 agent 適配](references/agent-compatibility.md)，按本地能力對應模型、技能載入、專案規範及持續執行方式；不得假設具備 Codex 工具或 Goal。

## 局部驗收優先

涉及實作或功能驗收時讀 [驗收、測試存檔與完成門檻](references/validation.md)。優先利用原存檔副本、固定初始狀態、可重現亂數或具明確來源的人工測試狀態，快速進入最小但足夠的驗證場景。不能只驗資料、按鈕或編譯；實際 Web 流程與跨狀態影響依功能範圍驗證。

**工程通關優先，正常難度最後：目標是驗證流程可達結局時，明確授權主控與子代理自行使用隔離測試存檔、debug／god mode，修改主角／隊友能力、HP 或鎖血、資金、物品、商店庫存／價格及相關測試狀態；不必為這些範圍內的測試修改逐次詢問。不能因打不贏、資源不足、練等或操作成本而反覆正常遊玩、停止或將可用 debug 方法的問題當成硬阻礙。沒有既有 debug 工具時，可建立最小、可撤銷且預設關閉的測試入口。**

修改數值以消除非驗收目標的難度，仍經真正操作觸發勝敗、事件、獎勵、跨場景、保存恢復及結局；直接改章節／已通關旗標只能用於情境準備，不能證明被跳過的流程。先全力排除流程障礙，正常數值的自然破關不是預設必要完成條件；若使用者／Goal 明確要求，保留為最後獨立待辦。加強狀態通關不能宣稱正常難度、平衡、死亡或成長機制已驗證。

每批跑相關檢查，整合里程碑跑整體回歸；同一批不讓所有代理重跑整套測試。新修改後重驗受影響流程。

## 現況與交接

`TODO.md` 是完成／部分完成／待辦的主入口。沒有時依實際證據建立，不臆造已完成項。以穩定編號、勾選、優先級與證據位置維護；大項拆成可驗證子項。新問題與使用者新交辦即加入，完成即更新。整體功能只有主控簽核後才勾選；底層通過不表示接入已完成。

每批更新：改了什麼、證據在哪、測試版本／情境／結果、未驗證部分、阻礙與下一步。歷史細節可留 `docs/`，TODO 指向它；避免重複維護多份現況清單。使用者要求長期規則時，在現有 `AGENTS.md` 適當位置記錄 TODO 維護與本 skill 路徑／名稱，不覆蓋既有規範。

## 操作邊界與停止

保留原遊戲、原始資料及玩家存檔；測試在副本、獨立儲存空間或隔離 origin 進行。執行原版前確認來源與環境；來源不明程式不可為了對照擅自執行。本 skill 不授權 push、部署、付費、擴張權限、發送對外訊息、創建獨立使用者 session 或排程；依使用者已有授權處理。這些邊界不禁止上述已授權的任務內子代理喚起與協作。

要求自主推進時，僅在以下情況停止：目前可合理推進範圍已完成且驗證；所有有價值後續都依賴使用者資料／授權／決策；或工具／環境／服務有不可繞過的硬限制。清楚報告是哪種情況、已驗證與未驗證成果、接續位置。有限預算或服務中斷前保留可恢復交接，不把未完成標為完成。

Goal 由使用者或上層明確要求才建立；skill 不自動啟動 Goal、背景持續執行或定時喚醒。已有 Goal 時維持原總目標，子代理完成單項後由主控接續循環，不能把總目標縮小為該單項。
